## Layout

```
apps/web            Next.js 15 back office + (later) POS PWA
apps/worker         pg-boss worker (no jobs registered until M2)
packages/config     shared tsconfig bases, ESLint flat config, Zod env schema, root .env loader, pino logger
packages/core       pure domain logic: money, ids (UUIDv7), Result/AppError
packages/db         Drizzle client, migrations, migrate/seed/reset scripts
packages/ui         shadcn/ui components + cn()
packages/notifications  created empty; implemented in M2
```

Internal packages are consumed as TypeScript source (`exports` → `src/*.ts`) and compiled by Next (`transpilePackages`) or `tsx`. That avoids a build step per package.

## Environment

- One `.env.local` at the repo root. `packages/config/load-env.ts` finds the workspace root and loads it with `process.loadEnvFile` (existing variables win, so CI values override). Next loads it via `@next/env` in `next.config.ts`.
- `packages/config/env.ts` holds Zod schemas: `clientEnvSchema` (only `NEXT_PUBLIC_*`) and `serverEnvSchema`. The web app validates both in `instrumentation.ts` (server start) and the worker/db scripts validate on boot. Missing variables cause a fail-fast with the list of keys (never values).

## Database (M0 scope)

- Migration `0000_foundation`: `pgcrypto`, a `reporting` schema, and an SQL `uuid_generate_v7()` function for server-side defaults. Business tables begin in M1.
- `pnpm db:migrate` uses `DIRECT_DATABASE_URL` (session/port 5432) with the Drizzle migrator.
- `pnpm db:seed` runs an ordered list of seed modules inside one transaction. The list is empty in M0. The demo tenant arrives with the M1/M3/M4 schema.
- `pnpm db:reset` drops app-managed schemas and re-migrates. It refuses to run unless `--force` is given and refuses when `NODE_ENV=production`.

## Web app shell

- Supabase SSR clients: browser (publishable key), server (cookie session, publishable key), admin (secret key, `import "server-only"`).
- `middleware.ts` refreshes the Supabase session and redirects to `/login` when no session exists.
- `(app)` route group: authenticated layout (server-side `getUser()` check), sidebar with Dashboard, POS, Inventory, Purchasing, Finance, Reports and Admin, a top bar with the user menu, and a theme toggle (light/dark/system via `next-themes`).
- A basic email + password sign-in and sign-out (server actions). MFA, invites, lockout and timeouts are M1.
- Module pages say which milestone delivers them. They show no fake data.

## Core

- `money`: `bigint` minor units + ISO currency, currency exponent table, parse/format, add/subtract/negate/compare, `multiply`/`divide` with an **explicit** rounding mode (no implicit default, so tax/pricing rounding stays a rule decision), `allocate` (largest remainder, exact sum), `roundToIncrement` (cash rounding).
- `id`: UUIDv7 generate/validate/extract timestamp.
- `result`: `Result<T,E>`, `AppError` with codes → HTTP status.
